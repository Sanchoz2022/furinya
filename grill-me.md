# Furinya TD AI Bot — Grill-Me Summary

> Этот файл содержит результаты grill-сессии по проекту миграции Kuni (C++) → Furinya (Rust).
> Цель: не перечитывать всё заново при следующем сете. Обновляй при смене решений.

## Контекст
- **Исходник:** `/home/sanchoz2022/kuni` — C++ проект "Kuni" (AI-компаньон, TDLib user-аккаунт, LLM, diary/RAG, vision, hearing, SD, proxy).
- **Цель:** Полный реврайт на Rust. НЕ побитовая совместимость — берём **поведение**, а не текст кода.
- **Почему реврайт:** Исходный C++ местами "нецензурный", после 7-8 правок уверенность в нём отпала. AUI framework тяжёлый.
- **Владелец:** Александр (papik_chat_id = 5005580127). Хост: Artix Linux, runit (НЕТ systemd), Xeon E5-2670 v3 12c/24t, RTX 3060, 24GB RAM.

## Ключевые решения (consensus)

| # | Тема | Решение |
|---|------|---------|
| 1 | TDLib | `tdjson` (JSON FFI), НЕ C++ static lib через AUI. Сборка TDLib локально ~20 мин CPU (ок). |
| 2 | Модели (GGUF) | `mv` (НЕ cp!) из `kuni` в `furinya_td_ai_bot/models/`. Автономность + docker-compose тащит изнутри. |
| 3 | Первый срез | ТОЛЬКО OpenAI-compatible chat-клиент. БЕЗ Telegram, БЕЗ diary. Вертикальный срез. |
| 4 | Структура | Workspace с саб-кратами + ОДИН корневой бинарник `furinya` (живёт до остановки/fatal). |
| 5 | Docker | Перенос `docker-compose.yml` + `Dockerfile` из `kuni` как есть. Модели локальными путями. |
| 6 | Конфиг | Формат TOML СОХРАНЯЕМ (секции `[general]`, `[general.llm]`, `[capabilities]`). Промпты не трогаем. |
| 7 | Git | Коммичу в локальный git свободно (хоть 100 коммитов). НЕ пушу (нет remote-ветки). |

## Архитектурные принципы (Rust)
- Tokio runtime, async traits, Result-based error handling, channels для общения между саб-кратами.
- Запрет `unsafe` (без согласования).
- Без `.clone()`-абузa, без `.unwrap()`-абуза (только `?` или match).
- `cargo clippy --all-targets -j 12` — ноль линтов.
- Корневой бинарник координирует саб-краты, они "сами поднимаются" через него.

## Защита от context-overflow (урок прошлой модели)
- Прошлая модель слилась из-за overflow и начала врать (`println!("всё ок")`).
- ПРАВИЛО: если чую overflow — ОСТАНАВЛИВАЮСЬ и говорю прямо. Не вру.
- Коммичу после КАЖДОГО рабочего шага (cargo check -j 12 → cargo test -j 12 → commit).
- `rm` в исключениях — папку не снесу.

## ТОМ 2 — Итог прожарки (продолжение, 2026-07-18)

> Вторая сессия прожарки: аудит готового текстового среза + правки по 4 пунктам (В1–В4).

### Что нашёл аудит (до правок)
- **Зацикливание #ask в kuni** (живой лог): system.md kuni требовал `#ask` ПЕРЕД каждым ответом → модель вечно звала `#ask`, мета-напоминание "be tool-centric" гнало её по новой. Furinya уже исправила это (system.md: "не зависишь от #ask, отвечай натурально").
- **Короткий reasoning в furinya** — КОРЕНЬ: furinya system.md ЗАПРЕТИЛ писать рассуждение текстом ("CRITICAL: NEVER write your reasoning as plain text"), полагаясь на native `reasoning_content`. Но Gemma-4-E4B через OAI API выдаёт reasoning_content очень коротким. kuni ЗАСТАВЛЯЛА модель писать `- thought:`/`- emotion:` и т.д. как явный текст → получалась "микро-поэма".
- **Промпты не подключены**: в `prompts.rs build_system_prompt()` собирались ТОЛЬКО system + character_base + character_appearance. `messages_epilogue` (анти-инъекция) и `anti_repeat` грузились, но НЕ вставлялись в контекст.
- **Нет таймстампов**: `tg_history_full: Vec<(i64,bool,String)>` — без date, в логе и контексте сообщения шли без `[ДД.ММ ЧЧ:ММ]`.
- **Fake-idle костыль**: idle-пробуждение делалось подделкой `updateNewMessage` от papik (`sender_id: papik`) → эффект как от реального посланного сообщения, и этот фейк пушился в историю, забивая контекст.

### Что сделано (В1–В4, все закоммичено отдельно)
- **В1 (reasoning)**: `prompts/system.md` — возвращён явный формат рассуждения (`- thought:`/`- emotion:`/`- to remember:`/`- intention:`) как ОБЯЗАТЕЛЬНАЯ часть ответа. Native `reasoning_content` оставлен бонусом.
- **В2 (промпты)**: `furinya-core/src/prompts.rs` `build_system_prompt()` теперь собирает system + character_base + character_appearance + **messages_epilogue** (анти-инъекция, всегда) + **anti_repeat**. Добавлен `chrono` в `furinya-tg/Cargo.toml`.
- **В4 (таймстампы)**: `agent.rs` — `tg_history_full: Vec<(i64,bool,String,i64)>` (добавлен `date`). Читается `message.date` из TDLib (новые сообщения + пагинация истории). Хелпер `format_ts()` → `[ДД.ММ ЧЧ:ММ]`. Таймстамп проставляется в лог и в текст сообщения (`[14.07 23:08] Александр: ...`).
- **В3 (idle/consolidate)**:
  - Убран fake-idle (было `sender_id: papik`). Теперь idle-стимул имеет `sender_id: 0` и НЕ пушится в `tg_history_full` (не забивает контекст).
  - Таймер тишины считается от `last_user_activity` (обновляется ТОЛЬКО на реальное сообщение papik, не на idle) → fake-spam больше не сбрасывает таймер сна.
  - Авто-консолидация через случайные **5–10 мин** тишины юзера (тихо, без сообщения).
  - Явный триггер "пошёл спать / отошёл / спать / ложусь" → consolidate + "иду спать". Плюс старые `!consolidate`/`!save`.
  - После консолидации: **рандомайзер ~30 мин** (30±10) → idle-инициатива (модель сама решает писать или нет). Потом долгое молчание → сон.
  - Добавлен `rand` в `furinya-tg/Cargo.toml`.

### Статус верификации

- `cargo clippy --all-targets -j 12` — **0 warnings, 0 errors** (починены: ptr_arg на execute_tg_tool/handle_new_message, unused `s`/`history_from_id`/`last_activity`, let_unit_value).
- `cargo test -j 12` — OK (0 passed/0 failed, функциональных тестов пока нет).
- ЖИВОЙ TG-тест не проводился (юзер запускает бинарник сам, смотрит логи). Инференс-бэкенды (:8090/:8091) подняты через docker-compose из kuni.

### Что НЕ сделано (следующие шаги)
